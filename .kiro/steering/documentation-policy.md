# Documentation Policy

## Creating Documentation Files

**DO NOT create markdown documentation files unless explicitly requested by the user.**

This includes:
- README files
- Summary documents
- Visual comparison documents
- Developer guides
- API documentation
- Tutorial files
- Any other markdown documentation

## Rationale

- Documentation files clutter the repository
- They waste time during implementation
- Users will ask for documentation when they need it
- Code should be self-documenting where possible
- Focus on working code, not documentation

## When to Create Documentation

Only create documentation files when:
1. The user explicitly asks for documentation
2. The user requests a specific type of document
3. It's part of a formal requirement (e.g., README for a published package)

## What to Do Instead

- Provide clear, concise summaries in chat responses
- Write good code comments where needed
- Focus on implementing features correctly
- Let the user decide what documentation they want
